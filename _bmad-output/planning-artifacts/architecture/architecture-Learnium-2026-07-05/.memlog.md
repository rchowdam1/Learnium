- (constraint) Existing Next.js App Router, Supabase auth/Postgres, Stripe billing, and separate Python RAG service are adopted reality for the launch architecture; this spine ratifies rather than replaces them.
- (decision) AD-1 binds all app implementation to a modular server-first layered monolith plus sidecar RAG service paradigm; prevents feature teams from creating competing clients, REST shapes, or direct database/RAG crossings.
- (decision) AD-2 binds identity, authorization, and user-owned data access to Supabase Auth plus server cookie client and middleware protectedPaths; prevents unprotected dashboard/profile/learning routes and browser-side privileged access.
- (decision) AD-3 binds quota-consuming LLM and billing-sensitive actions to check-before-spend, persist-before-decrement, decrement-after-success ordering; prevents quota loss on rejection/failure and double-spend across retries.
- (decision) AD-4 binds XP, level, streak, badge, lesson completion, set completion, and review scheduling mutations to server-authoritative idempotent event handlers; prevents client-forged progress and duplicate reward awards.
- (decision) AD-5 binds generated Sets, Lessons, Path outlines, and Review question banks to schema validation, quality gates, and reportable persisted content before display; prevents malformed or untraceable AI content from becoming user progress state.
- (decision) AD-6 binds Study Buddy and future LLM endpoints to the RAG sidecar boundary, semantic cache first, lesson-context grounding, and manually mirrored schemas; prevents direct model calls from UI/API routes and divergent chat payloads.
- (decision) AD-7 binds billing tier truth to Stripe webhook-confirmed subscription state mapped into Supabase quota/tier fields; prevents client-return or checkout-session success from prematurely granting Plus capabilities.
- (decision) AD-8 binds public/social surfaces to privacy-minimized projection tables or queries exposing only display name, level, badges, streak, completed set count, and weekly XP by consent; prevents leakage of chat, learning history, private profiles, or protected profile data.
- (decision) AD-9 binds Review Sessions to zero-quota question banks generated or refreshed before the session and scheduled via server-owned recurrence state; prevents daily retention from requiring a live LLM call or generation quota.
- (decision) AD-10 binds operational configuration to environment variables per deployed service, with Next.js calling a configured RAG service URL and service-role Supabase access restricted to server-only privileged modules; prevents localhost-only deploys and service-role leakage.
- (assumption) Fast path assumption: fixed-interval spaced repetition is sufficient for v1 unless later learning efficacy requirements demand SM-2-style scheduling.
- (assumption) Fast path assumption: global UTC weekly league reset is the launch default because per-user timezone resets complicate cohort fairness.
- (assumption) Fast path assumption: no native mobile app in v1; responsive web plus email reminders is the architecture target until push/PWA is deliberately adopted.
- (question) Open: exact Free/Plus quota numbers, pricing, fair-use cap, and LLM cost ceiling need unit-economics confirmation before final billing constants are hardcoded.
- (question) Open: streak protection mechanic remains product-owned; architecture only requires idempotent streak events and a soft-loss state.
- (question) Open: production hosting topology for the Python RAG service and Redis/Chroma persistence must be selected before deploy hardening.

- (decision) AD-12 binds user-owned object reads/writes to parent ownership proof for setId, lessonId, quizId, buddyId, chatId, and profile-derived records; prevents trusting client-supplied ids across users.
- (decision) AD-13 binds quota counters to single-owner atomic server/database mutations such as consume_set_quota, reset_set_quota_if_due, and consume_chat_quota; prevents read-modify-write overspend and mutation from read endpoints.
