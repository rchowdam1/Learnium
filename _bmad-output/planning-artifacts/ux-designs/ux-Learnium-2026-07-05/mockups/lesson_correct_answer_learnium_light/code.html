Database Sharding Strategies

When dealing with massive scale, single monolithic databases eventually hit physical limits. This forces architects to choose between vertical scaling (scaling up) and horizontal scaling (scaling out).

Vertical Scaling

Upgrading the existing server with more CPU, RAM, or storage. It's simpler to implement but has a hard ceiling constraint based on available hardware technology.

Horizontal Scaling (Sharding)

Distributing the dataset across multiple independent machines (shards). It provides virtually limitless capacity but introduces significant architectural complexity.

Sharding requires designing a partition key that evenly distributes data and load. Poorly chosen shard keys can lead to "hotspots," where one server is overwhelmed while others remain idle, defeating the purpose of distributed infrastructure.
